# 04-permissions — 权限管理

## 概述

当用户意图涉及**谁能访问哪个知识库**、**谁能写入**时，使用本文档。

### 权限矩阵（收到 403 时参考）

| 操作 | 系统管理员 | 群组 admin | 普通用户 |
|------|-----------|-----------|---------|
| 授权/撤销群组访问知识库 | ✅ | ❌ | ❌ |
| 授予/撤销写入权限 | ✅ | ✅（仅限自己管理的群组） | ❌ |
| 查看全部群组列表 | ✅ | ❌ | ❌ |
| 查看群组成员 | ✅ | ✅（仅限自己管理的群组） | ❌ |
| 查看自己的权限 | ✅ | ✅ | ✅ |

> **Agent 不需要预先判断自己的身份。** 直接按用户意图调用 API，后端会自动校验权限。如果返回 403，参考上表向用户说明需要何种权限。

---

## 前置查询

### 获取群组列表

```
GET /api/groups
```

- **系统管理员**：返回全部群组
- **普通用户**：只返回自己所在的群组

> 授权操作需要 `group_id`。执行授权前先调此接口获取目标群组。

### 获取群组成员

```
GET /api/groups/{group_id}/members
```

授予写入权限前，需要确认目标用户是否在该群组中。

> 群组 admin 只能查看自己管理的群组成员。

---

## 授权群组访问知识库

**权限要求：仅系统管理员**

```
POST /api/groups/{group_id}/collections
```

```json
{
  "collection_id": 1
}
```

授权后群组现有成员自动获得 read 权限。

> 如返回 403，说明当前用户不是系统管理员，无权执行此操作。

---

## 撤销群组授权

**权限要求：仅系统管理员**

```
DELETE /api/groups/{group_id}/collections/{collection_id}
```

会同时清理该群组在该知识库下的所有权限记录。

> 如返回 403，说明当前用户不是系统管理员，无权执行此操作。

---

## 授予写入权限

**权限要求：系统管理员 或 该群组 admin**

```
POST /api/groups/{group_id}/collections/{collection_id}/writers
```

```json
{
  "user_id": "13800138000"
}
```

**前提：** 该用户必须是群组成员，且知识库已授权给该群组。

> 如返回 403，说明当前用户既不是系统管理员，也不是该群组的 admin。

---

## 撤销写入权限

**权限要求：系统管理员 或 该群组 admin**

```
DELETE /api/groups/{group_id}/collections/{collection_id}/writers/{user_id}
```

只删除 write 权限，保留 read 权限。

> 如返回 403，说明当前用户既不是系统管理员，也不是该群组的 admin。

---

## 查看当前用户权限

**权限要求：任意登录用户**

```
GET /api/me/collection-permissions
```

返回当前用户在所有知识库上的权限列表。
